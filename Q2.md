1. Что такое класс?
Это шаблон (чертеж), описывающий данные (атрибуты) и поведение (методы) объектов определенного типа. Например, класс Venue описывает любую площадку.

2. Что такое объект?
Это конкретный экземпляр класса, созданный в памяти. Объект обладает конкретными значениями атрибутов. Например, объект venue1 с названием «Лофт» и вместимостью 50.

3. Чем класс отличается от объекта?
Класс — это абстрактное описание, а объект — это реальная сущность, созданная по этому описанию. Класс существует в коде один, а объектов этого класса можно создать сколько угодно.

4. Что такое экземпляр класса?
Это синоним объекта. «Создать экземпляр класса» = «Создать объект».

5. Для чего используется __init__()?
Это конструктор (метод инициализации). Он вызывается автоматически при создании объекта (obj = ClassName(...)) и служит для присвоения начальных значений атрибутам объекта.

6. Что такое self?
Это ссылка на текущий объект. Через self методы класса получают доступ к атрибутам и другим методам конкретного объекта. Python передает self автоматически при вызове метода.

7. Чем атрибут класса отличается от атрибута объекта?
Атрибут класса задается вне методов (внутри класса) и общий для всех объектов. Атрибут объекта задается через self в __init__ и уникален для каждого экземпляра.

8. Что такое метод объекта?
Это функция, определенная внутри класса, которая первым аргументом принимает self и работает с данными конкретного объекта.

9. Чем метод отличается от обычной функции?
Метод привязан к классу, имеет доступ к состоянию объекта (через self) и вызывается через точку (object.method()). Функция вызывается сама по себе (function()).

10. В каких случаях функцию следует сделать методом класса?
Если функция выполняет операции над данными конкретного объекта. Например, проверка, подходит ли площадка по вместимости — это поведение самой площадки (venue.is_suitable_for()).

11. Для чего используется __str__()?
Для определения «человекочитаемого» строкового представления объекта. Он вызывается функциями print() или str().

12. Что происходит при выполнении print(object)?
Python ищет у объекта метод __str__(). Если он есть, выводится результат его работы. Если нет — выводится техническая информация (адрес в памяти и тип объекта).

13. Что такое конструктор объекта?
Это метод __init__. Его задача — сформировать объект и задать его начальное состояние.

14. Можно ли создать несколько объектов одного класса?
Да, любое количество раз. venue1 = Venue(1, "Лофт", 50), venue2 = Venue(2, "Офис", 20).

15. Могут ли объекты одного класса иметь разные значения атрибутов?
Да, это основная идея. У venue1 вместимость 50, а у venue2 — 20.

16. Что такое инкапсуляция?
Это принцип сокрытия внутренней реализации объекта и предоставления к ней доступа только через определенные методы. В Python это реализуется с помощью _ (защищенные) и __ (приватные) атрибутов.

17. Как инкапсуляция проявляется в проекте?
Например, в классе Registration атрибут is_cancelled изменяется только через метод cancel(), а не напрямую из main.py.

18. Что такое наследование?
Это механизм, позволяющий создать новый класс (дочерний) на основе существующего (родительского), перенимая его атрибуты и методы.

19. Что означает отношение «является» при наследовании?
Это проверка, оправдано ли наследование. Если дочерний класс «является» частным случаем родительского (например, Admin является User), наследование уместно.

20. Почему не следует использовать наследование без предметного основания?
Это приведет к запутанной архитектуре (нарушению принципа LSP). Наследование ради экономии строк кода — плохая практика. В нашем проекте нет нужды наследовать, например, Event от Venue.

21. Что такое полиморфизм?
Это способность объектов с одинаковым интерфейсом (например, с одинаковыми названиями методов) вести себя по-разному.

22. Как __str__() связан с полиморфизмом?
У разных классов (Venue, User, Event) есть свой метод __str__. Функция print() не знает, какой объект ей передали, но вызывает нужный __str__, и каждый объект выводит себя по-своему. Это полиморфизм.

23. Что такое композиция?
Это принцип, при котором объект содержит в себе другие объекты (отношение «содержит» или «часть-целое»). Например, Event содержит Venue.

24. Чем композиция отличается от наследования?
Наследование — это «Является» (is-a). Композиция — это «Содержит» (has-a). В нашем проекте Registration содержит объекты Event и User.

25. Как композиция используется в классе Booking (или в нашем случае Registration)?
Атрибут event хранит ссылку на объект Event, а атрибут user — ссылку на объект User. Это позволяет, например, узнать имя участника прямо из регистрации: registration.user.name.

26. Что такое декоратор?
Это функция, которая принимает другую функцию и расширяет ее поведение, не изменяя ее исходный код. Оборачивает функцию.

27. Для чего используется декоратор?
Для добавления сквозной функциональности: логирование, проверка прав доступа, кэширование, замер времени выполнения.

28. Что такое функция-обертка?
Это внутренняя функция (обычно wrapper), которая создается внутри декоратора и вызывается вместо оригинальной функции, выполняя код до и после нее.

29. Для чего используются *args и **kwargs в декораторах?
Чтобы функция-обертка могла принимать любое количество позиционных и именованных аргументов, которые были переданы в оригинальную функцию, и передавать их дальше без изменений.

30. Для чего используется functools.wraps?
Он сохраняет метаданные оригинальной функции (ее имя __name__, документацию __doc__) при оборачивании в декоратор. Без него тесты и IDE будут видеть имя wrapper.

31. Для чего применяется @staticmethod?
Для методов, которые логически относятся к классу, но не используют данные конкретного объекта (не принимают self). Например, валидация формата email.

32. Чем staticmethod отличается от обычного метода?
Обычный метод требует объект (self), а staticmethod можно вызывать прямо от класса: User.validate_email(...). Он не может менять состояние объекта.

33. Для чего используется @classmethod?
Для методов, которые принимают первым аргументом сам класс (cls), а не объект. Часто используется как альтернативный конструктор — например, from_data() для создания объекта из словаря JSON.

34. Чем classmethod отличается от метода объекта?
Метод объекта принимает self (экземпляр) и работает с его данными. Classmethod принимает cls (класс) и может создавать новые экземпляры или работать с атрибутами класса.

35. Для чего используется @property?
Он превращает метод в атрибут. Позволяет обращаться к методу без круглых скобок (obj.status). Используется для контроля доступа к данным (геттеры/сеттеры).

36. Почему booking.status может использоваться без круглых скобок?
Потому что метод помечен декоратором @property. Извне кажется, что это обычное поле данных, но внутри выполняется код метода.

37. Какие сущности выделены в индивидуальном проекте?
Пользователь (User), Мероприятие (Event), Площадка (Venue), Регистрация (Registration).

38. Почему Venue представлен классом?
Потому что у площадки есть свои данные (название, вместимость) и поведение (проверка, подходит ли она по вместимости).

39. Какие атрибуты имеет Venue?
id (уникальный идентификатор), name (название), capacity (вместимость).

40. Какие операции относятся непосредственно к Venue?
Проверка вместимости (метод is_suitable_for), строковое представление (__str__).

41. Почему Registration хранит объект Event, а не только его идентификатор?
Чтобы через регистрацию мы могли сразу получить доступ к деталям мероприятия (например, вывести его название) без необходимости искать мероприятие по ID в огромном списке.

42. Почему Registration связан с объектом User?
По той же причине: чтобы при выводе списка участников мы могли сразу обратиться к имени пользователя через registration.user.name.

43. Какие функции ПР2 были преобразованы в методы?
Проверка вместимости (is_suitable_for в классе Venue), проверка и отмена регистрации (cancel в классе Registration).

44. Какие функции ПР2 остались обычными функциями и почему?
Функции поиска, фильтрации, сохранения и загрузки из JSON, а также ввод данных. Они работают с коллекциями объектов (списками), а не с одним объектом. Логика сохранения в файл не является поведением конкретного мероприятия.

45. Как выполняется преобразование JSON в объекты?
В storage.py мы читаем словарь и передаем его значения в конструктор класса. Для связанных объектов (Event и Venue) мы сначала находим объект Venue по venue_id, а затем передаем его при создании Event.

46. Как выполняется сохранение объектов в JSON?
В storage.py мы формируем словарь вручную: берем атрибуты объекта и складываем их в dict. Если атрибут является объектом (например, registration.user), мы сохраняем не сам объект, а его id (registration.user.id).

47. Как изменились коллекции данных по сравнению с ПР2?
Вместо List[dict] теперь используются List[User], List[Venue], List[Event], List[Registration]. Это позволяет IDE подсказывать нам атрибуты при написании кода.

48. Какие тесты были адаптированы после перехода к ООП?
Тесты, которые обращались к словарям (room["name"]), переписаны на обращение к атрибутам (room.name). Добавлены тесты на создание объектов и проверку методов (например, test_venue_is_suitable).

49. Как проверить, что старая функциональность проекта не была потеряна?
Запустить старые сценарии: добавить мероприятие, проверить свободные места, зарегистрировать участника. Плюс запустить pytest, где все старые тесты переписаны под новый синтаксис.

50. Какова роль main.py после перехода к объектной модели?
Он стал "оркестратором". Он не хранит данные в словарях, а оперирует коллекциями объектов: запрашивает у пользователя ID, находит объекты в списках, вызывает их методы и передает их функциям для сохранения.
